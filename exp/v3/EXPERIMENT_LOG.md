## P1 数据构建与长度审计

## P0 容量试验开始

- 4096 档完成第一轮权重装载。vLLM 日志报告加载权重约 39.71 秒，模型装载约占 10.0152 GiB，随后进入服务容量初始化。
- 固定 V0、XFormers、FP16、4 GiB CPU offload、`max-num-seqs=8`、eager。4096、8192、16384 各测一个满长合成请求及 10、30、60 段档相应的最长真实问答提示，再同时提交该档最长的 8 条真实提示。按账面 token、峰值显存和调度器采样记录是否通过。此条为运行开始记录，逐档结果继续追加。

### 4096 档通过

- 服务报上限 4096。10 段档最长真实提示为 2,488 输入 token，返回 21 输出 token，单请求 10.886 秒。满长合成请求用尽 3,968 + 128 tokens，完成用时 56.543 秒。
- 八条真实请求全部返回，输入 token 与 P1 对齐。批次墙钟 20.772 秒，采样到 8 条同时执行，采样峰值 14,807 MiB。调度器在首段预填充期间有排队，随后达到 8 条并发。
- 请求全部完成后，执行器终止自身 vLLM。引擎退出记录 `MQLLMEngine terminated` 和 NCCL 清理警告，随后服务关闭，显存回到 2 MiB。8192 档接续开始。

### 8192 档通过，长提示有排队

- 服务报上限 8192。30 段档最长真实提示为 5,420 输入 token，返回 21 输出 token，用时 13.149 秒。满长合成请求为 8,064 + 128 tokens，用时 60.000 秒。
- 八条真实请求全部返回，批次墙钟 46.054 秒。采样最多 5 条同时执行、最多 6 条等待，两个峰值发生时刻可以不同。GPU KV cache 采样峰值 91.59%，显存峰值 14,825 MiB。服务关闭后显存回到 2 MiB。
- P1 的 10／30 段各 50 题可在此上限构成共同档，按 P1 长度报告入组。此次容量试验验证了两档最长代表输入，正式的整条路径延迟和质量仍由 P1.5 测量。16384 档接续开始。

### 16384 档首次启动失败

- 同一 4 GiB CPU offload 配置下，vLLM 在初始化 KV cache 时报告只够 **8,016 tokens**，小于配置的 16,384；服务退出 1，未发出生成请求。启动阶段采样峰值 14,205 MiB，退出后显存回到 2 MiB。
- 保留首轮结果，下一次仅把 CPU offload 从 **4 GiB 调到 6 GiB** 释放显存。原版权重、CUDA 路径、客户端并发、样本保持一致。6 GiB 如通过，作为单独的长上下文服务配置记录。

### 16384 档复测已启动

- 发起 6 GiB CPU offload 复测，使用独立输出目录保留首轮失败。vLLM 完成缓存初始化，日志报告每条占满 16,384 tokens 时的 KV 理论并发为 2.62。该值是缓存容量估计，真实同时运行数由后续请求采样。
- 已观测到长上下文单请求在生成。待收集真实提示、满长合成请求、八请求批次的完整响应及峰值。

### 16384 复测通过，P0 实机验收完成

- 6 GiB offload 下，vLLM 预留 2,684 个 GPU KV blocks，服务报 16384，启动 51.075 秒。60 段档最长提示实测为 10,828 输入、18 输出 tokens，耗时 19.477 秒。满长合成请求为 16,256 + 128 tokens，耗时 89.262 秒，采样显存峰值 14,919 MiB。
- 同时提交的八条真实请求全部返回，批次墙钟 86.187 秒。采样最多 4 条同时执行，批次峰值 14,395 MiB，GPU KV cache 峰值 93.59%。6 GiB 仅用于长上下文复测，另行保留 4 GiB 环境的结果。
- 本轮所有测试服务结束后显存均回到 2 MiB。首轮和复测共 37 个原始文件的传输 SHA-256 一致，复算每个阶段遥测峰值，并以 P1 记录逐条核对真实输入的题号、prompt 哈希和 API 计数。见 [P0 实机验收](p0/gpu_runtime.md)、[首轮证据](p0/live-2026-11-16/primary-evidence.sha256) 和 [复测证据](p0/live-2026-11-16/offload6-evidence.sha256)。
- P1.5 可在统一的 8192／4 GiB 环境做 10 段、30 段各 50 题对照。60 段全量对照适用已验收的 16384／6 GiB 配置，该配置的策略成本需单独测量。P0 容量试验未读取 gold 或计算答案质量。

## P1.5 执行登记

- 复用 P0 的 T4 环境，启动前显存 2 MiB，P0 固定权重和依赖仍可用。先在 8192／4 GiB 对 10、30 段各跑完整 50 题，60 段在 16384／6 GiB 对同一批题单独运行。后者的部署设置有差异，成本按档内方法比较。
- **先完成检索证据审计，再锁定策略。** 在 10／30／60 段池上，V2 `2+1` 同时命中两段金标证据分别为 31／21／22 题。一次补查加两段得到 37／25／29，加四段得到 43／34／32，因此登记 `2+2` 与 `2+4` 为扩展分支。以上为基于配套金标的离线检索召回。
- 锁定固定 BM25 top-2／4／6、Full、V2 原规则直接读合并三段，以及实际执行首答并再查一次的 `2+1/2/4`。同一 Qwen、提示、温度 0、输出 128。每条接续补查路径单独计入两次答题请求；调度在同题区块间轮换各路径顺序，每批至多 8。预热独立登记。
- 质量使用固定官方答案 EM/F1，检索及引用的金标标题召回单独登记。调度、缓存和请求文件不含 gold。原始开发题 `5ae610e55542995703ce8ae1` 的已知答案异常作为事前登记的敏感性分析；主结果仍用全 50 题。记录失败、重试、累计实际 token、墙钟和 A/B 事后选择上界；此阶段不实施门控或句级核验。见 [运行协议](p1_5/protocol.json)。

### P1.5 质量与成本验收完成

- 25 个回收文件通过 SHA-256。题号、规模、池和提示词散列、上下文顺序、token 用量和预先登记的方法覆盖复验一致。正式预检 1,200 条路径、1,650 次 Qwen 调用，另有 12 次预热。累计 1,590,626 输入／29,102 输出 token（预热另列）。168 个测量批次合计墙钟 62 分 11 秒。未发生 HTTP、提示词校验或答题解析失败。
- **30 段主结果**。Full F1 56.73%，4,341 输入 token、32.47 秒。两阶段 2+4 F1 59.92%，1,316 输入 token、23.59 秒。配对 F1 差值 +3.19 个百分点，探索性 95% 区间 [−11.27, +17.77]。2+4 有 13 题改善、35 题持平、2 题退化。其 Oracle 为 62.13%，原 2+1 Oracle 为 49.59%。
- **另两档**。10 段以 2+4 获得本档最高 F1 70.68%，V2 直读 2+1 获 63.18% 和 10.49 秒。60 段独立诊断中，2+2 获 F1 58.65%、约 1,034 输入 token 和 28.55 秒，Oracle 为 62.86%。

## P2 关系与证据核验

- 在独立目录启动同一 T4 上的 8192／4 GiB Qwen 服务。方案指定的 DeBERTa 原版权重完成 SHA-256 核对。局部 NLI 使用 CPU 4 线程，每题最多 4 次，每条 premise+hypothesis 总长最多 512 token。
- 锁定 30 段的 50 道 P1.5 开发题和原首答 A。原两阶段 2+4 的同题 F1 增益为主诊断目标，2+2 作敏感性。用固定哈希抽 30 道待人工抽查，并登记同预算 10/50 的特征比较、E≥0.5 的诊断阈值及 V2 整题 NLI 加桥接信号回退。未读取封存题或选择阈值寻优。见 [P2 协议](p2/protocol.json)。
- 在线输入中只保留首轮题干、原文、草稿与引用；独立直读对照读取同一套 P1 候选池。15 个上传文件通过哈希校验。开始各 50 次关系抽取、Qwen 自检、原规则直读 2+2 与 2+4。每个关系输出预算 512 tokens。同名和指代标记、原文 ID 白名单、无完整证据时的明确缺失与回退均保存。

### 结构接口偏差与修正

- 前 32 条返回均未通过严格校验。其中 18 条根字段不符，14 条 JSON 语法无效。原始示例有缺桥接实体字段、JSON 后带说明文字、非法引用值写法。首轮所有记录和成本继续保留。
- 在读取任何 P2 增益诊断前，另登记 XGrammar 约束 JSON 复测。约束桥接字段、1–4 条关系、candidate／unresolved 字段及单题允许的原文编号。关系 ID 由列表顺序生成，重复编号可机械去重；陈述、实体和证据内容由原响应决定并保留原始输出。两种 schema 已在远端固定 XGrammar 成功编译。用同一 50 题复测关系及自检，直接生成对照沿用首轮同哈希记录。
- 提交独立在途队列，等待首轮推理和 CPU NLI 收尾后再使用同一 T4，分别保存日志与输出。首轮 Qwen 完成，四类任务各 50 次成功返回；HTTP 成功与结构通过率分别核算。
- 离线另复算 V2 已锁定的单 NLI 阈值及实际触发量。相同预算的比较仍统一以分数切点选 10 道，平分按事先固定的题号哈希裁决。
