# V3.1 · P1 候选池与证据审计

## 样本和来源

按 V2 pilot 原顺序，选取前 50 个拥有十段原始候选且通过去重检查的 bridge 题。共检查前 55 个 ID。跳过 1 个原始只有 6 段的题，以及 4 个原始候选内触发重复或近重复约束的题，具体 ID 写在 [pool_manifest.json](artifacts/pool_manifest.json)。保留入选题所有十段原文、标题、句序和归档答案。此批 ID 与早期使用前 50 行的 Kaggle 记录不同。

补充材料来自 [HotpotQA distractor 的固定训练分片](https://huggingface.co/datasets/hotpotqa/hotpot_qa/commit/14f0ace3c3fac7bd86149c616b5b05d8282e5c6a)。训练分片共 90,447 个唯一源题 ID，与上游 validation 的 ID 无交集。对训练源题 ID 做固定哈希排序，取前 4,096 个，只投影 `id` 和 `context`。对规范化标题与正文组合去重，得到 **38,229 个**供体段落。来源版本和分片散列、采样 ID 集合散列、供体索引散列均已保留。

## 入池、去重和随机化

- 在 38,229 段全索引上使用 V2 BM25 分词和 `BM25Okapi` 给每题排名。困难候选只用问题字符串。随机候选按题号、段落 ID 和固定种子哈希排序。新增段落按困难、随机交替选入。每题在 **30 段**档新增 **10 + 10**，在 **60 段**档累计新增 **25 + 25**。重复冲突时沿对应排名继续取下一候选。
- 池内以规范化标题或正文相同、5 词 shingle Jaccard ≥ 0.80、至少 20 个 shingle 的包含率 ≥ 0.90、共用 ≥12 词规范化完整句筛去重复及近重复。初轮验收发现三个标题不同的酒店段落复用了同一句所有权文字，因此新增**补充段落不得复用该题任一原文规范化完整句**的检查。它比较全部原文，不依赖支持句有哪些。沿用原题筛选条件、语料、排名和种子重建，未根据模型成绩调整数据。
- 候选池先按成员嵌套，再按预设位置种子 73 对每题和段落 ID 排序。每个小池的段落在大池中保持相对次序。随机排序不读取金标，排名在不同规模各自完整候选池上重算。配置见 [config.json](config.json)，实际出处见 [provenance.jsonl](artifacts/provenance.jsonl)。

## 证据和潜在替代线索

每题的全部原始支持句在三个规模均可定位。50 题共有 **123 条标准支持句**，分布于 **100 个题目—段落配对**。每档的 100 个位置按原文位置五等分统计如下。逐题位置见 [证据位置记录](artifacts/evaluation_only/evidence_positions.jsonl)。

| 标称且实际段数 | 第 1 个五分位 | 第 2 个 | 第 3 个 | 第 4 个 | 第 5 个 |
|---|---:|---:|---:|---:|---:|
| 10 | 24 | 21 | 24 | 18 | 13 |
| 30 | 22 | 24 | 22 | 17 | 15 |
| 60 | 24 | 20 | 22 | 17 | 17 |

审计全部 2,500 次新增段落投放，**0 条标准支持句的规范化逐字副本**。答案短语扫描标记 **15 个段落、8 道题**（10 个来自 BM25，5 个来自随机）。逐段检查了这 15 项，在其中没有找到能够独立建立问题所问关系的证据。比如，其他 Wichita 高中段落没有给出题目中两所指定高中的地址；其他运动员、作品和日期多为同词异指。但其他获奖者的两段材料能提供“印度最高平民荣誉”的名称，因此可能给模型提供局部答案线索。相关线索如实保留，见 [短语匹配案卷](artifacts/evaluation_only/phrase_review.jsonl)。文字匹配与有限人工检查无法穷尽同义改写或资料组合带来的语义支持。

原始 pilot 有一道题问“哪个城市”而归档答案为 `Pennsylvania's`，证据句虽然可定位，题意与答案明显不对齐。本次沿用归档答案并在此登记题号 `5ae610e55542995703ce8ae1`，供评估前固定敏感性口径。另有 P0 登记的 V2 tune 句索引 902 异常，未出现在这 50 个开发题中。

## 划分和访问边界

- **当前开发**为上述 50 个 V2 pilot ID。用同一题号的 10／30／60 段版本做比较，全部归在同一划分。P1.5 使用这批开发题作工程判断。
- **条件性门控开发**按 `gate-split` 和 seed 42 的题号哈希将 V2 tune 划为 **400 训练／100 验证**，并标记 **100／50** 小跑子集。本次执行的是 ID 划分。生成标签和优化门控取决于 P1.5 与 P2。
- **最终测试**保留规划规模约 300。按 P0 查到的历史排除清单，尚有 4,318 个 bridge ID。最终题号清单保持空白，待额外的团队历史排除和样本量锁定后再封存。P1 对该上游文件只读取 ID 和题型两列来检查分割。
- 在线工件的根对象与段落／句子字段均按白名单校验。答案和支持句只在 [evaluation_only](artifacts/evaluation_only)；`split_plan.json` 记录分组 ID，与在线提示对象分离。
