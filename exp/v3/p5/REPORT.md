## 封存与校准

- 在 4,318 道已审计历史以外的 bridge 候选中，按固定哈希顺序筛选。取前 300 道原段落、证据索引和完整提示符合固定规则的题。入样前排除 23 道原段落近重复和 1 道原段落数量异常，顺延补足。300 题均和 P0 审计的历史题号互斥。
- 30 段为主比较，同一批主样本中预先抽出 60 道有完整 10／30／60 段输入的配对诊断题。主档使用 8192／4 GiB，60 段使用 16384／6 GiB。三档最长完整回答提示加输出预留分别为 2,985、6,042、10,960 token。扩大候选池沿用同一 P1 donor 索引、去重规则和顺序。
- 封存 60 道引用充分性盲审题，其中 20 道双人独立复核。另独立封存 50 道主档端到端实测题。所有标注及计时子样本选择均在正式结果之前完成。
- P4 三个完整 Sugeno 权重与仅四后件 seed 42、固定 Fuzzy、线性回归、NLI 和简化规则等均锁定。Qwen 自检另对原验证集 50 道题做补校准。12 种打分方法各锁定 10%／20%／30%／50% 的分数边界，历史 V2 原门控单列原阈值。每道最终题独立按阈值触发，跨档共用权重和边界，实际触发率可能偏离校准预算。
- 主要开发差异的标准差为 20.48 个 F1 百分点，按 300 题粗算普通 95% 区间半宽约 2.32 个百分点。Sugeno 与线性回归在开发样本上的所选题相同，开发样本的零差异无法估计两者在新题上的方差。300 题用于当前预算可行的正式主比较，统计解释依照最终实际区间。

## 运行与成本口径

共享问答路径逐题使用无上下文、固定 top-2／3／6、Full、原 2+1 直读和原查询 2+4 直读，句级证据统一用 V2 选择器从最终作答引用的可见段落选择。主门控共享 A、B4 和各自首轮信号，历史原 V2 用 B1。模型提示和检索锁定，运行期间按各请求的长度与累计输入余额限制调用。在线包含候选原文、定位 ID、长度、配置和代码。金标只在本地离线评分。

冻结 420 个题号／档位组合，对应 2,940 个基础答题请求，签名提示的输入合计 3,332,722 token。句级选择、自检、重试和真实在线门控计时另计。50 题实测五条门控路径时，依实际触发执行 A、核验、B 与句级选择，保留端到端路径秒数。各预算点的 token、NLI 调用与分支选择由共用缓存重放；回放耗时单列。服务档位不同的跨档结果按实测环境解释。

机器评分器使用官方 HotpotQA 答案 EM/F1 和支持句指标，并计算主比较的同题配对区间。评审者材料隐藏策略名称和正式评分。

训练和部署成本分开核算。P3 的 100 道训练题与 50 道验证题共有 300 次 Qwen 作答请求，输入 197,460 token、输出 5,269 token，19 个测量批次合计 519.18 秒，另有两次预热。对应 CPU NLI 输入 23,545 token。P4 的 18 次 CPU 拟合合计 5.44 秒，预定 Sugeno seed 42 的最终配置耗时 0.284 秒。P5 继续使用这些权重，没有新增训练。Qwen 自检在原验证集的校准成本列在其归档，P5 部署比较仅计每题实际所经路径，没有按 token 换算金额。[P3 标签和成本汇总](../p3/analysis/summary.json) · [P4 拟合计时](../p4/remote-evidence/output/runtime.json)

## 复算命令

从仓库根目录执行。将复算输出写到新目录，可以逐字节和正式归档比较。离线步骤读取本地评分标签，不需要 GPU 或重新生成答案。

```bash
recheck_p5=$(mktemp -d)
(cd exp/v3/p5/remote-evidence && shasum -a 256 -c evidence.sha256)
python3.13 -B exp/v3/p5/audit_run.py --evidence exp/v3/p5/remote-evidence \
  >"$recheck_p5/raw-audit.json"
python3.13 -B exp/v3/p5/evaluate.py --input exp/v3/p5/input \
  --raw exp/v3/p5/remote-evidence/live --out "$recheck_p5/analysis"
Rscript exp/v3/p5/plot_final.R "$recheck_p5/analysis/quality_cost.csv" \
  "$recheck_p5/curves.png"
```
