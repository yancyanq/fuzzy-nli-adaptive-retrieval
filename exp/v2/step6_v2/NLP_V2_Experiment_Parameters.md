## 1 数据和样本规模

| 参数 | 实际设置 | 作用 |
| --- | --- | --- |
| 数据源 | Hugging Face 的 `hotpotqa/hotpot_qa`，`distractor` 配置，公开 `validation` 划分 | 每题自带含相关证据和干扰段落的小候选池，且公开金标允许用固定官方评分器核对 |
| 题型 | 只用 `type == bridge`。公开 validation 共 7,405 题，其中 bridge 5,918 题 | 集中考察跨段证据连接。报告的范围随此筛选而限定 |
| 划分与随机种子 | seed **42** 打乱后顺序留出 **pilot 100、dev 500、test 1,000**。按 `_id` 验证三批互不重叠 | pilot 检查可行性。dev 搜索并锁定参数。test 估计锁定后表现 |
| 预处理 | 保留原段落、原句顺序及金标 `(标题, 零起始句索引)` | 检索可用分词，句级评测仍能映射到原文 |
| 少于十段的题 | 正式 test 里 998 题有十段，各有一题为四段、两段。两段题仍保留，首轮已用完时 B 无新段可补 | 保留原始候选池和配对清单。正式触发率按选择 B 的路径计数 |

**为何用这份数据。** 官方测试答案不公开，使用公开 validation 中独立保留的子集可以给全部 A/B 输出评分。官网原始 JSON 也是候选。HF 版本便于加载和按既定规则切分。BEIR、KILT、FlashRAG 等其他版本与本次依赖的逐题原始 distractor 候选池不匹配。混入 comparison 题会扩大范围，也会把跨段桥接与比较题的证据结构混在一起。来源、范围和分割时点以 11 月 14 日的数据登记及 11 月 15 日正式清单验证为准。 [实验日志](../../EXPERIMENT_LOG.md)

**为何是 100／500／1,000。** 完整 pilot 取 V2 建议范围 50–100 题的上端，并包含早期已经发出的 30 题。日志没有单独给 pilot 100 对 80 的功效比较，也没有给 dev 500 对其他 dev 规模的比较。500 道 dev 题为三种门控提供同一独立校准集，正式前把 20% 转化为固定的 100 次选择。

正式 test 的 1,000 题有单独的备选评估。若 pilot 的 16% 改善比例保持不变，500 和 1,000 题分别约有 80 和 160 个正例。采用 pilot 的 Oracle−A 配对差标准差作计划参考，近似区间半宽为 **0.02877 与 0.02034 F1**，后者窄约 29%。代价是三支正式问答从 **1,500 增至 3,000 次**。本轮 GPU 时间无固定上限，因此在正式结果出现前采用 1,000 题。这是跨阶段的精度参考，实际门控的配对方差需要正式数据，尤其是 Fuzzy 对同输入硬规则。 [规模比较与批准记录](../../EXPERIMENT_LOG.md) · [三份数据的复现记录](Reproducibility_Checklist.md)

## 2 检索和 A/B 上下文预算

| 参数 | 实际设置 | 为什么这样设置及备选影响 |
| --- | --- | --- |
| 检索实现 | `rank_bm25==0.2.2` 的 `BM25Okapi`，以题目自带候选池为范围 | BM25 是 V2 原型可运行的词匹配基线。稠密检索当时仍是 stub。改用稠密模型会增加依赖、改变候选排序，需重新缓存和校准 |
| BM25 实现默认值 | `k1=1.5`、`b=0.75`、`epsilon=0.25` | `k1` 控制词频收益趋于饱和的速度，`b` 控制文档长度归一化，`epsilon` 参与当前实现替换负 IDF 的规则。代码继承库默认值，日志没有登记这三个值的独立比较 |
| 检索分词 | 小写后取正则 `[a-z0-9]+` 的词，去掉固定停用词。段落文本为标题加原句拼接。排序同分保留候选原次序 | 两轮共用一套轻量词匹配入口，方便逐题复算与对齐。改分词或停用词可能改变首名段落，进而连带改变第二次查询 |
| 首轮 A | 查询为问题，取 **`k=2` 段** | 首轮允许跨两段读证，同时给追加一段留出余量 |
| 再检索 B | 查询为**问题 + 首轮第 1 名段落标题 + 首句**。首句缺失时该部分为空。仅在未用段落上重建 BM25 并取 **`m=1` 段**，与 A 的两段合并 | 借用首段提供的实体或上下文词扩展查询，保留原有证据并保证新增段落不重复。LLM 生成追问也可扩展查询，但会增加模型调用和额外变数 |
| Full-context | 依题目原顺序读入全部候选，用同一题干模板和作答模型生成一次 | 检验小候选池中直接阅读所有证据的表现。改模型、模板或段落顺序都会增加对照变量 |

**为什么定为 2+1。** 在 pilot 100 题测过首轮 `k∈{2,3,4}`，以及追加 `m∈{1,2}`。首轮两段双金标覆盖 **31%**，规则改写再取一段后为 **59%**。同样只读三段的单轮 top-3 为 **45%**。这给了同预算下采用两轮查询的实际依据。若继续追加第二段，`k=2,m=2` 的双金标覆盖达到 **70%**，代价是每道触发题多读一段，预算更接近较大的单轮上下文。采用 `m=1` 保持追加路径轻量并便于比较。这些数衡量金标段落检索覆盖，最终答案收益另由 A/B 的官方 F1 评估。 [m=1 逐题与汇总](../../step2/step2_results/summary.json) · [m=2 汇总](../../step2/step2_m2/summary.json) · [检索实现](../compare_models.py)

## 3 作答模型和 NLI

### 3.1 作答模型与解码

| 参数 | 阶段与实际设置 | 理由及记录范围 |
| --- | --- | --- |
| 早期试跑与原 pilot 模型 | `deepseek-chat`。先跑前 30 题的两支，再复用成功答案补至 100 对 | API 先快速验证数据、检索、作答、解析和评分闭环。日志列过 GPT-4o-mini 候选，只有 DeepSeek 同阶段真实试跑数据 |
| dev／正式模型 | `Qwen/Qwen2.5-7B-Instruct`，revision `a09a35458c702b33eeacc393d103063234e8bc28`，原始未量化权重 | 租用 GPU 上本地部署便于保留模型和服务身份、校验权重并实测真实路径。更小模型或量化可能改变答案和 logprob，不能直接替代固定权重下的结果 |
| 温度与输出上限 | 温度 **0**，最大输出 **128 tokens**。正式客户端未显式传 `top_p` 或解码 seed | 固定贪心解码减少采样选择，并限制短答案和结构化引用输出的长度。128 保留合理输出空间，同时参与上下文预检。日志没有比较 128 与其他输出上限的独立评估 |
| 答题提示 | A、B、Full 使用相同模板，输出 JSON `{answer, citations}`，回答引用当前段落序号 | 保持同一问答接口，让各路径的上下文或选支差异可解释。改为在主回答中直接生成原文句索引会改变已校准的问答输出分布 |
| 缓存和生成次数 | 正式每个题目 A、B、Full 各保存一份输出。模型身份、题号、分支作为主要键 | 共享 A/B 能让门控在相同待选答案上比较，并支撑漏选、Oracle 和配对区间。多次生成可研究生成方差，但会增加使用量并需要另定汇总口径 |

**温度与确定性的边界。** 在固定输出上，评分器确定性地算出相同 F1。温度 0 仍要与固定检查点、执行环境和已保存输出配合描述。DeepSeek 实际重跑中有答案变化，GPU 批处理也可能引入数值舍入差别。因此正式证据以锁定条件下的原始缓存为准。 [模型比较及重跑日志](../../EXPERIMENT_LOG.md) · [请求实现](../compare_models.py) · [门控锁](../step4_dev/gates/locked_gates.json)

| 参数 | 实际设置 | 选择依据与备选影响 |
| --- | --- | --- |
| 检查点 | `MoritzLaurer/DeBERTa-v3-large-mnli-fever-anli-ling-wanli`，正式 revision `b3546ea6b0346eb6f8d5d68b13c7dc6d0376b3d7` | 早期登记看重检查点的多来源训练与本地可推理性。更小的 NLI 是潜在显存备选，本次没有不同检查点的同批精度对照 |

## 4 标签与预实验 GO

### 4.1 所有阶段共用的标签规则

| 参数 | 锁定设置 | 选择理由 |
| --- | --- | --- |
| 逐题增益 | `ΔF1 = F1(B) − F1(A)` | 门控要识别「B 的最终答案是否更好」。用“找到了新金标段落”做正类会把检索成功和作答成功混在一起。用 EM 从 0 翻到 1 则会忽略有部分得分提高的题 |
| 持平容差 | **`ε=0`**。ΔF1 大于 0 为改善，等于 0 为持平，小于 0 为变差。门控正类是严格改善 | 确保任何已经保存的官方分差都保留在任务定义中。正容差如 .1 会把部分小幅变化计为持平，改变改善题分母、门控召回率与 Oracle 选支。「腿伤」人工复核例显示这个口径会保留措辞导致的分差。原日志把 `.1` 留作条件性的敏感性方案，主口径一直为 0 |
| A/B Oracle | 逐题以官方答案 F1 取优。持平时选 **A** | 同分时选 A 会减少无 F1 收益的追加。选 B 会提高 Oracle 的触发率，但其平均答案 F1 不会随之上升。Oracle 只在固定 A/B 的预算内给出上界 |

同一套标签用于 pilot 和正式输出。精确率的分母是策略实际触发数，召回率的分母是所有严格改善题。端到端答案 F1 则为全体题的平均分。 [11 月 15 日 09:40 预注册](../../EXPERIMENT_LOG.md) · [正式评分实现](../evaluate_test_v2.py)

### 4.2 原始 100 题 GO 的门槛

11 月 15 日 **09:40** 登记，早于 100 题汇总。四条须同时满足。点估计下限、改善比例下限及变差计数比上限是团队**主观、预注册**的判断值。

| 检查 | 预注册条件 | 值的来由及备选影响 | 实测读数 |
| --- | --- | --- | --- |
| A/B 中可争取的质量量级 | Oracle−A 的点估计 **≥0.05 F1** | .05 是团队认为值得投入后续门控工作的最低效应。原日志结合 100 题的粗略误差量级 .03–.04 设定。该量级本身是前期估计。只要求区间下界高于零，可能让精确但实际很小的主张通过 | +.137 |
| 对增益方向的可信度 | 配对 **95%** 区间下界 **严格 >0** | 与 .05 点估计下限结合，兼顾效应量与题级不确定性。单用点估计会忽略估计误差 | 下界 +.077 |
| 可改善题规模 | 改善占比 **≥10%** | 给之后的门控校准和 P/R 计算留出足够正例。若比例仅 3%，1,000 题按比例只有约 30 个正例。10% 按同样假设约 100 个。部署到另一批题时实际比例仍以观测为准 | 16/100 |
| 追加检索的变差风险 | 变差题数 ÷ 改善题数 **≤0.5** | 限制追加路径频繁改坏。用计数比约束出现频率，配合均值与区间看变化幅度。计数比单独无法决定平均 F1 | 2/16 = .125 |

**预实验区间和返工。** Oracle−A 用逐题配对 bootstrap，重复 **10,000 次**、seed **42**，取双侧 95% 区间。若任一检查失败，规则改写最多改 **一次**，重算 A/B 并沿用原门槛。多次修改会提高对同批 pilot 的适应程度。实际四项通过，返工路径未触发。 [GO 的登记与读出](../../EXPERIMENT_LOG.md) · [100 题逐题表](../../step5/step5_pilot/per_question.csv)

**人工 NLI 抽查规模。** 原登记按三类候选抽约 **20 条**，每类约 6–7 条，用于观察误判机制。实际为 20 个「题目×分支」记录，涉及 **15 道题**。全量随机人工标注可用于推断总体错误率，但需要不同的抽样和审核流程。原 V2 的不可接受错误比例缺少事先锁定值，这批审核按定性证据解读。 [早期审核记录](../../step5/audit_review.csv) · [抽查设计与核对](../../EXPERIMENT_LOG.md)

## 5 模型不确定性接口诊断

### 5.1 从 DeepSeek 占位异常到复查

| 环节 | 参数与做法 | 为什么这样设置 |
| --- | --- | --- |
| pilot 首轮信号读出 | 以改善 vs 持平为主，A 侧分数取反来衡量「越低越值得检索」。AUC bootstrap **5,000 次**、seed **42**，95% 区间 | 先看第一轮信号是否有区分度。将少量变差题单列，避免极少数观测左右主对比。AUC 本身不选择阈值 |
| 说明性阈值 | A entailment 低于 **.50／.80／.90／.95** 的规则用于 pilot 读出 | 用多个固定阈值展示触发数量怎么变。这组值未进入正式门控校准。日志未给出四个例示点相对其他点的选值比较 |
| DeepSeek 小探测 | 两个短 prompt，各在温度 **0 和 1** 请求，最大 **8 tokens**，请求 `top_logprobs=5` | 初步查异常是否随温度改变。11:48 的“非零候选”包含 −9999 占位，12:08 已更正 |
| Step 5b 专项复跑 | 100 题 × A/B，共 **200 次**。模型、温度 **0**、上限 **128**、检索和 prompt 都沿用。加 `logprobs=True`、`top_logprobs=5`，单独写缓存 | 目的是验证候选 margin 是否能在原温度下提供新信息。升温会改变答案采样，导致与原 pilot 的匹配下降。只做 NLI 可省下 200 次调用，但无法直接确认这些候选是否退化 |

### 5.2 Step 6a 本地服务的 PASS 条件

本地 Qwen 暂用 **dev 前 30 题、偏移 0、只跑 A**，温度 **0**、输出上限 **128**，请求 top-5。固定次序和只跑 A 能用 30 次实测查接口。正式门控所需信息在第一轮就要可用。扩大到更多题或生成 B 可以补数据，但接口初筛只用于判定退化。阈值在本地实测之前登记，属于主观、工程性的通过条件。

| 检查 | 通过条件 | 为什么选这个值或口径 | 实测 |
| --- | --- | --- | --- |
| 选中值被夹为零 | 答案片段内恰为 0 的选中 token 比例 **≤50%** | 允许少数高置信 token 在保留精度下舍入成 0，同时排除多数值被接口钳住的情况。要求零个精确 0 会错拒正常的舍入值。只看全局方差则可能漏掉大量钳制 | 28/127 = 22.05% |
| 候选占位 | `logprob ≤ −9000` 的候选比例 **<5%** | −9000 用于识别此前见到的 −9999 哨兵，且远离通常候选值。严格零容忍会把少量异常也判为整批不可用。只看选中 token 无法发现候选侧占位 | 0/2595 |
| 逐题平均选中值 | 保留 **6 位小数**后至少 **10 个**不同值，总体方差 **>0** | 要求 30 题的均值有可辨别的分布。只要方差非零会让两种值通过。要求 30 题全不同又会排除正常重复。六位精度沿用已归档 token 提取器 | 30 个，方差 .023727663329 |

## 7 正式门控及锁定参数

### 7.1 输入、隶属函数和分数

11 月 15 日 **16:26** 在查看 dev 结果前登记校准规格。

1. **输入风险。** 以首轮 A 的 `r = 1 − p(entailment)` 为连续风险。沿用 §6 的标题桥接代理，以 `z=0` 表示已找到桥接、`z=1` 表示未找到。金标、B 答案和 B 分数用于 dev 选参及正式评分，在线决策只看 A。
2. **Fuzzy 连续隶属度。** `h = clip((r − lo)/(hi − lo), 0, 1)`，低风险隶属度为 `1−h`。两个锚点之间的风险变化连续地影响分数，超出锚点则饱和。
3. **零阶 Sugeno。** 以乘积计算规则激活、对常数后件作归一化加权平均。桥接存在时，NLI 低/高的后件是 `0, 1−w`。桥接未找到时为 `w, 1`。合成得到 `s=(1−w)h+wz`。桥接不可计算时回退为 `s=h`。
4. **同输入硬规则。** 输入和四规则形式相同，`h` 切为二值 `1[r ≥ (lo+hi)/2]`。Fuzzy、硬规则各自在同一搜索空间锁定参数，因此最终锚点与权重可以不同。**NLI 单阈值**直接排列 `r`。

**为什么这样配对。** 若把 Fuzzy 只与单 NLI 阈值比较，输入、规则和实际预算都可能不同。增加同输入硬规则让两个系统共享 A/B、信号和规则结构，在同一 dev 预算下比较连续与离散决策。把离散切分放在锚点中点，也让同一组候选锚点有清楚的硬门控对应形式。采用四条规则和常数后件便于追溯每项输入如何改变排序。原日志没有同批 Mamdani、Sugeno 或更多隶属函数形状的性能对照，所以推理形式应报告为实验设计。 [门控设计登记](../../EXPERIMENT_LOG.md) · [公式的实际实现](../calibrate_gates_v2.py)

## 8 正式评估、选句与消融

### 8.1 正式对照、标签和指标

正式质量在 **1,000 道保留题**上用固定官方 HotpotQA 评分器。评分器固定到 commit `fa3a36370899e1d85822de61e58c85ea19993154`。用官方归一化计算 **答案 F1、EM、句级 supporting-fact F1**。F1 允许词重叠的部分得分，EM 要求归一化后完全匹配。句级 Supp-F1 评价所选支持事实集合。这样保留共同基准，并让另外的 NLI 诊断有独立含义。若引入语义判分，措辞敏感度可能改变，但也会改变标签、Oracle 和已锁定的统计比较。

六种可执行策略是 **Never、Always、NLI 单阈值、同输入硬规则、Fuzzy、Full-context**。另有 **A/B Oracle** 与 **两种 Fuzzy 消融**，共九组官方预测。Never 与 Always 给出 A 和 B 的端点，Oracle 给出 A/B 预算内的事后选优，单 NLI 和同输入硬规则分别回答单信号基线和相同输入下的差异，Full-context 给出完整候选池基准。省略 Full-context 会失去小候选池上“直接读完”的质量和开销参照。 [正式评估登记](../../EXPERIMENT_LOG.md) · [固定官方评分器](../step5_v2/hotpot_evaluate_v1.py) · [九组正式预测](../step5_v2/predictions)

| 成本报告 | 秒数的 **均值、P50、P90、P95**。LLM 问答／选择器调用与输入、输出 token。NLI 调用和实际消费的输入 token 单列。NLI 消费长度最多 **512** | 均值与分位数揭示不同的耗时属性。检索率只描述是否选 B。用 token 或调用衡量负担会补足实际计算差异 |

正式全量的 **23.0%** 与实时子集的 **21.875%** 都是 Fuzzy 的观测触发率，所用分母分别是 **1,000** 和 **32**。成本按单次真实运行描述，适用环境为上述设备和负载。 [计时登记与实测日志](../../EXPERIMENT_LOG.md) · [实时日志](../step5_v2/latency_test_v2.jsonl) · [成本汇总](../step5_v2/latency_summary.json)

### 9.2 正式配对区间的参数

- **比较范围。** 在 11 月 15 日 **20:16** 的正式推理前登记五项答案 F1 对照：Fuzzy−同输入硬规则、Fuzzy−NLI 阈值、Fuzzy−Never、A/B Oracle−Never、Full-context−Fuzzy。对应同输入、单信号、首轮锚点、A/B 最佳余量和全上下文基准，预先约定可减少只挑结果好看的对照。
- **抽样单位。** 以 test 清单原顺序的 **1,000 道题**为配对单位。先对同题算两策略 F1 差，再有放回取 **1,000 个差值**计算均值。若分别对两组答案抽样，会打破同一题的配对并引入不同的题目难度。
- **重采样设置。** 正式重复 **10,000** 次，seed **42**，线性插值取 **2.5%／97.5%** 分位形成双侧 **95%** 百分位区间。沿用原 GO 的 bootstrap 约定。更少复制能省计算但给分位数带来更大 Monte Carlo 波动。更多复制不能增加独立试题数量。精确次数属于事前分析设置，没有验证为唯一最优。
- **报告口径。** 将 F1 差乘 **100** 后用百分点表示。五项各自报告单项区间，没有多重比较校正，也没有事前设定等效或非劣效界线。区间跨零时可说明效应方向不确定。用同一批冻结策略与缓存重采样，区间不覆盖重新调参、重新生成或更换硬件带来的波动。

### 9.3 错误分析的抽样参数

正式汇总可见后，在逐例审读前登记以下五组。按各组内部 `SHA-256("42:<ID>")`、ID 升序取样，允许重叠并记录，实际共 **22 道不同题**。数量是探索性案例预算。

| 分层 | 候选条件 | 抽取数与理由 |
| --- | --- | --- |
| Fuzzy 漏选改善 | B 比 A 的答案 F1 高，Fuzzy 选 A | **5**，定位门控漏掉的机会 |
| Fuzzy 触发变差 | B 比 A 小，Fuzzy 选 B | **5**，观察追加后为何改坏 |
| 缺一跳候选 | A 引用有效段落，其中恰有一个金标标题 | **4**，检查跨段信息是否有缺口 |
| 错误引用候选 | A 引用有效段落，但未引任何金标标题 | **4**，比对已引段落是否支持题目问的关系 |
| 两段支持候选 | A 对金标的 EM 为 1，且 A 引用了两个金标标题 | **4**，逐句核实两段能否联合支持，并看最终句级引用是否覆盖连接 |

## 10 复现时应核对的版本与口径

| 事项 | 应核对什么 | 这样核对的意义 |
| --- | --- | --- |
| 数据身份 | 确认实际清单是原 pilot 100、tune 500、test 1,000，且题号无交叉。seed 42 还分别用于哈希顺序和 bootstrap。正式生成未显式设置解码 seed | 同一个 seed 在不同操作内有不同作用。数据复现需要固定清单与哈希，尤其是正式题目和切分顺序 |
| 门控身份 | 从 `locked_gates.json` 加载两信号、模型版本、源码哈希和完整边界四元组。正式输入清单校验锁文件与服务脚本 | 用文档里舍入的阈值或现调规则会改变边界题。锁文件才是可执行定义 |
| 请求和重试 | 问答与选句应用层超时 **120 秒**，最多 **3 次尝试**。临时错退避、logprobs 不支持时回退单列，SDK 自身行为与应用层分开记 | 短超时会增加失败弃用，过长会延迟发现卡住。现有值是运行设置，日志没有对其他超时或重试次数做性能对照。逐条保存并从成功记录恢复可减少同一题重复生成 |
| 缓存失效 | 答案／证据／NLI 以作答模型、题号、分支识别，NLI 模型身份另存。计时另用 NLI 设备、题号、策略作为键。数据、权重、问答设置、BM25／改写或 NLI 配置改变时，从受影响阶段启用新缓存 | 改门控可复用固定输出。改检索会连带改变上下文、答案和证据。独立标识让恢复步骤不把不同运行混在一起 |
| 版本边界 | 正式评分器有上游固定 commit，正式实验脚本以源码与配置 SHA-256 识别。当前归档中没有与本次正式运行一一对应的 Git commit | 已知版本、哈希和文件可复核，范围由实际保存的记录确定 |
| 已验证方式 | 从既有缓存复算 dev 锁、正式官方评分与统计产物。真实计时可由 192 条存档重新聚合 | 该证据验证从保存的模型输出复现结果。以权重重新推理和重新实测延迟属于另一层验证 |
